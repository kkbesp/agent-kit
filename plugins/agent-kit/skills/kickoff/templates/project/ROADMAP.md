
1. Прочитать [AGENTS.md](AGENTS.md), выполнить сводку. Своя незавершённая задача — продолжить; чужую не перехватывать. Иначе взять первую свободную из сводки или ту, что поручил владелец.
2. Открыть одну карточку по ID и прочитать только названные в ней решения, уроки и документы. Весь roadmap для старта не читать.
3. Перед записью перечитать STATUS/OWNER/CLAIM и `git status`. Записать OWNER (уникальное имя сессии), CLAIM (пути, исходный SHA, время) и один NEXT.
4. Пользовательский переход → проверка → коммит → обновить эту же карточку. DONE — только после всей приёмки карточки. При остановке — NEXT и точный BLOCKER.

Порядок работы: [delivery](docs/engineering/delivery.md). **Приоритет при противоречии:** прямое поручение владельца → границы версий ниже → приёмка карточки → предметные документы. Расхождение исправляется в исходном документе, а не новой копией правила.

## Как читать порядок и зависимости

Положение карточки в файле задаёт приоритет среди доступных. DEPS — только обязательные готовые входы: если приёмке нужен результат другой карточки, она в DEPS; общая предметная область сама по себе зависимостью не делает. Общие механизмы (ошибки, права, уведомления) вводятся вместе с первым потребителем, не отдельной фазой.

Приёмка выполняется локально: свой компьютер, тестовые данные, браузер, контейнеры. Отсутствие production-доступа, платного бюджета или устройства записывается в EVIDENCE как внешний остаток и не блокирует локальный DONE; известный дефект — блокирует.
