# Порядок выполнения задач

Единица результата — действие пользователя от начала до сохранённого итога. Техническая работа выполняется как часть такого результата или для устранения конкретного блокера. Задачи и статусы — только в [ROADMAP.md](../../ROADMAP.md); этот документ целиком не перечитывать, открывать нужный раздел.

## Критерий завершения

Пользователь проходит обещанное действие; результат сохранён и доступен после повторного открытия. Проверены относящиеся ошибки, права и повторы. Изменённый интерфейс просмотрен. Файлы лежат по назначению, чужие правки сохранены. В ответе — эффект, выполненные проверки и реальные ограничения; число тестов и размер diff — только вспомогательно.

Готовность разработки, локальная проверка, устройство, внешний сервис и выпуск учитываются отдельно. Недоступный внешний этап не отменяет сделанную функцию и не позволяет объявить весь продукт готовым.

## Как агент берёт задачу

Статусы: `TODO` → `IN_PROGRESS` → `REVIEW` → `DONE`; `BLOCKED` — конкретное препятствие, записанное в карточке. ID постоянные, не перенумеровываются.

1. Прочитать `AGENTS.md`, карточку, названные в ней решения и уроки. Принятые подходы не выбирать заново.
2. `git status`, DEPS карточки, занятость файлов. Записать `OWNER` (уникальное имя сессии) и `CLAIM` (пути, исходный SHA, время). Зависимую задачу не начинать до DONE предшественников.
3. Карточка — готовый brief: результат, scope, входы, ownership, приёмка, проверка, STOP. Один исполнитель ведёт один сквозной путь.
4. **Интегратор один:** общие манифесты и lockfile, маршруты, порядок миграций, общий API-контракт и ROADMAP меняет интегратор или явно передаёт конкретные файлы.
5. Сначала готовое средство из [solutions](solutions.md); затем документация, registry, peer dependencies и лицензия версии. Зависимость — с первым потребителем.
6. Проверка по риску: формат/линт/типы затронутого → профильный сценарий → просмотр результата. Права, сессии, деньги и внешние эффекты — с отрицательными проверками. Полный набор — на интеграционной границе.
7. Перед `DONE`: результат перечитан через пользовательский путь; существенный diff прошёл независимое ревью; UI просмотрен на mobile (390×844) и desktop (1440×900), PDF — каждая страница. В карточку — одна строка `EVIDENCE`. Срез закоммичен.

**Реалистичная приёмка:** для каждого критерия назвать место, доступные данные/инструменты и наблюдаемый результат. По умолчанию — локальный компьютер, браузер, контейнеры, тестовые данные; локальный инструмент ставит исполнитель. Не требовать несуществующий стенд и не устраивать отказы в production. Отсутствие production-доступа, бюджета или устройства записывается как внешний остаток; функцию не подменять заглушкой и replay не называть live-проверкой.

**Общий стоп:** занятый файл, нерешённая существенная неоднозначность, нарушение принятого решения или дефект останавливают только зависимую часть: записать BLOCKER и продолжить доступную работу.

## Защита темпа

- **Короткий вход.** Сводка навигатора → карточка → названные документы. Не выводить целиком roadmap, lockfile и успешные логи.
- **Один видимый срез.** В карточке одна строка `NEXT: кто → действие → сохранённый итог; прямая проверка`. Сначала минимальный путь UI → API → БД → результат, затем обязательные отказы. Не строить backend всех разделов отдельно от их экранов.
- **Проверка темпа.** Ориентир — 45–60 минут до первого воспроизводимого результата среза. Нет результата — назвать один разрыв и уменьшить проход. Повторный интервал без нового доказательства — сменить метод или BLOCKED для зависимой части.
- **Ограничить незавершённое.** Один основной срез на исполнителя; перед следующим — интегрировать проверенный результат. Не делить один сценарий на цепочку исследователь → planner → backend → UI → tester.
- **Не ждать агента вместо работы.** Делегированное ждать по ID процесса, не опросом; свою непересекающуюся часть делать параллельно.
- **Проверять один раз на нужной границе.** Успешный неизменённый прогон не повторять; исправление ревью проверяется по изменённой области.
- **Не открывать поздние блокеры.** При первом подключении внешнего сервиса сразу проверить доступ, sandbox и контракт; отсутствие — записать внешний остаток сразу и продолжить с рабочим адаптером.

**Перед следующим срезом:** есть место, где открыть сохранённый итог; обязательные отказы проверены; результат интегрирован; scope не расширен без причины; записан следующий переход или точный блокер.

## Делегирование агентам

1. **Один срез на агента.** Карточку режут по её «Порядку внутри карточки»; один агент на всю карточку с auth/деньгами не запускать.
2. **Решения до кода.** Нерешённый выбор (провайдер, права, метод восстановления) — сначала вопрос владельцу.
3. **Угрозы в brief** для auth, сессий, секретов, платежей, телеметрии с персональными данными — чек-лист ниже.
4. **Verifier после каждого среза**, до следующего и до DONE. Ему отдают код и критерии, не вывод исполнителя.
5. **Исправления — свежему агенту** с компактным handoff (дефект file:line, критерий, файлы, проверка).
6. **Модель по риску:** auth, секреты, платежи, миграции, конкурентность — `deep`; обычные срезы — `build`; однозначная мелочь — `quick`.

### Чек-лист угроз для brief

- Фильтры чувствительных данных — allowlist полей, не regex-чёрный список.
- Граница доверия на сервере: прямой запрос в обход клиента упирается в серверную проверку прав и лимитов.
- Гонки отзыва: действие в начатом запросе после logout/revoke перепроверяет статус под блокировкой.
- Одноразовые коды гасятся вне откатываемой транзакции; лимит на попытку и источник.
- Нет состояния, в котором частичная настройка даёт полный доступ.
- Время в тестах фиксировано, не `Date.now()` на границе окна.

## Продолжение без переписки

Для передачи достаточно заменить поля той же карточки:

```md
- **STATUS:** IN_PROGRESS · **OWNER:** claude-auth-1 · **DEPS:** {{PREFIX}}-001 · **CLAIM:** точные пути; исходный SHA; дата/время.
- **NEXT:** следующий пользовательский переход и прямая проверка.
- **BLOCKER:** нет / точная причина; что нужно для продолжения.
- **EVIDENCE:** SHA; команда/exit; артефакт; внешний остаток.
```

Чужой OWNER сохраняется до явной передачи; возраст CLAIM не даёт права отобрать работу. EVIDENCE не заполняется выдуманным успехом. Дневник в карточке не наращивать — заменять актуальную строку.
