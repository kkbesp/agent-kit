# Lesson: ошибка не должна повториться

Сначала исправление и проверка исходного сбоя (skill `systematic-debugging`), потом урок. Урок без исправления не пишется.

1. **Найди причину, а не симптом.** Какое правило не было прочитано, какая проверка пропущена, какое допущение оказалось ложным.
2. **Проверь, нет ли уже такой строки** в «Частых ошибках» `AGENTS.md` проекта (и в глобальных правилах). Есть — это повтор: не добавляй вторую фразу, а закрепи проверкой — тест, lint-правило, скрипт, шаг в `verify`, хук. Укажи проверку в существующей строке.
3. **Новая строка — одна**, в форме:
   `<что делали неправильно> → <как правильно> → <чем проверить>`
   Конкретно и проверяемо: имена файлов, команды, размеры. Без дат-дневников, имён сессий и извинений.
4. **Место:** ошибка про этот проект — `AGENTS.md` проекта. Про работу агента везде — личный блок владельца в `~/.claude/CLAUDE.md` / `~/.codex/AGENTS.md`, только если владелец попросил. Предметный опыт (почему решение такое) — в `docs/product/lessons.md` и ссылка из карточки.
5. Коммит вместе с исправлением или отдельным маленьким коммитом.

Плохо: «Нужно внимательнее проверять UI».
Хорошо: «Сдача UI по build и HTTP 200 → смотреть скриншоты 390×844 и 1440×900, открыть каждое выпадающее меню → skill ui-qa, скриншоты в .artifacts/».
