# Take: одна карточка от взятия до сохранённого итога

Если в проекте нет `ROADMAP.md` и `scripts/roadmap.mjs` — это не тот skill: предложи `kickoff`.

## Вход

1. `node scripts/roadmap.mjs` (или `pnpm roadmap`). Своя незавершённая карточка (по уникальному OWNER) — продолжить её. Иначе — поручённый ID или первая свободная.
2. `node scripts/roadmap.mjs <ID>` — прочитать только карточку и названные в ней решения, уроки, разделы документов. «Частые ошибки» в `AGENTS.md` — обязательно.
3. `git status`, свежий STATUS/OWNER/CLAIM. Чужое не перехватывать.

## Взятие

Записать в карточку (одна правка, без дневника):

```md
- **STATUS:** IN_PROGRESS · **OWNER:** <агент>-<тема>-<дата> · **DEPS:** … · **CLAIM:** пути; исходный SHA; время.
- **NEXT:** кто → действие → сохранённый итог; прямая проверка.
```

Если в карточке есть нерешённый выбор владельца — сначала вопрос, потом код.

## Срез

- Первый проход «Порядка внутри карточки»: минимальный сквозной путь до видимого результата. Готовое средство из `solutions.md`; новая зависимость — по `source-driven-development`.
- Логика и баги — test-first на реальный риск; не писать тесты ради числа.
- Проверка: дешёвые (формат/линт/типы затронутого) → профильный сценарий → просмотр результата (UI — skill `ui-qa`, mobile и desktop).
- Существенный diff — `verifier` в свежем контексте с критериями карточки; FAIL — исправить, проверить изменённую область.
- Коммит среза. Следующий проход — только после интеграции текущего.

Ориентир 45–60 минут до первого воспроизводимого результата. Нет результата — назвать разрыв, уменьшить проход; дважды без прогресса — сменить метод или BLOCKED для зависимой части.

## Итог в карточке

- Проход готов, карточка нет: `EVIDENCE (проход N): SHA; команда/exit; что видно` и новый NEXT.
- Вся приёмка пройдена: `STATUS: DONE`, итоговый `EVIDENCE`, `NEXT: нет`.
- Остановка: `NEXT` и точный `BLOCKER` с условием возобновления.

Ответ владельцу: что теперь может пользователь → чем проверено → что осталось. Без отчёта отдельным файлом.
